PetPaws CI/CD: Architecture Diagram

ระบบ Jenkins สำหรับ PetPaws API (NestJS, backend/api) และ PetPaws Mobile (Flutter) · Lab 10 · สำหรับทีม Operation

Gate: ไม่ผ่านแล้วหยุด pipeline รันขนาน (parallel) stage ทั่วไป เส้นประ = เส้นทางสำรอง / ข้อมูลอ่านอย่างเดียว

จุดสำคัญของสถาปัตยกรรม

  • Secret ไม่อยู่ใน Git: อ้างผ่าน Jenkins Credentials เท่านั้น (github-token, sonar-token, cosign-key, cosign-password, kubeconfig, e2e-env, localstack-aws, slack-webhook, android-keystore, android-keystore-password) ใน log จะแสดงเป็น ****
  • Zero-downtime deploy: deploy ลงสีที่ไม่ได้รับทราฟฟิก, smoke test ผ่าน Service ประจำสีนั้นก่อน แล้วจึงสลับ selector.color ของ Service petpaws
  • Production มีสองด่าน: Pipeline Health Gate (20 build ล่าสุดต้องสำเร็จ ≥ 90%) และคนกดอนุมัติ ทั้งสองทำเฉพาะ branch main
  • Supply chain: SBOM (CycloneDX) ถูกลงนามด้วย Cosign และตรวจด้วยกฎ OPA; image ถูกสแกนโดย Trivy (HIGH/CRITICAL = บล็อก)
  • Infrastructure: Terraform state อยู่ใน S3 (เปิด versioning) พร้อม DynamoDB lock; apply เฉพาะไฟล์ plan ที่ผ่านการอนุมัติ

Rollback Runbook

ขั้นตอนย้อนกลับเมื่อ release มีปัญหา · คำสั่งทั้งหมดรันบนเครื่อง ops ที่มี kubectl --context kind-petpaws

อาการ / สัญญาณประเภทใช้ขั้นตอน
Smoke test สีใหม่ล้ม (Slack: stage Blue/Green Deploy FAILURE)อัตโนมัติR1: ตรวจว่า rollback อัตโนมัติสำเร็จ
Deploy ผ่านแล้ว แต่ผู้ใช้เจอ error / latency สูงคนทำR2: สลับทราฟฟิกกลับสีเดิม
ทั้งสองสีมีเวอร์ชันเสียคนทำR3: ย้อน image ด้วย rollout undo / build commit เก่า
แอปมือถือรุ่นใหม่มีปัญหาคนทำR4
เปลี่ยน infrastructure แล้วพัง / state lock ค้างคนทำR5

R1: Rollback อัตโนมัติจาก pipeline

เมื่อ stage Blue/Green Deploy ล้ม, post { failure } จะ log ROLLBACK: deploy to <สีใหม่> failed, restoring traffic to <สีเดิม> แล้ว patch Service กลับสีเดิมและ rollout undo deployment ของสีใหม่ ผู้ใช้จึงไม่ถูกส่งไปยังเวอร์ชันเสีย ops ตรวจยืนยัน:

kubectl get svc petpaws -o jsonpath='{.spec.selector.color}'   # ต้องเป็นสีเดิม
kubectl get pods -l app=petpaws-api -L color                     # สีเดิมต้อง Running/Ready

R2: สลับทราฟฟิกกลับสีเดิม (ใช้เวลา < 1 นาที)

  1. ดูสีปัจจุบัน: kubectl get svc petpaws -o jsonpath='{.spec.selector.color}' (สมมติได้ green สีเดิมคือ blue)
  2. ตรวจว่าสีเดิมยังพร้อม: kubectl rollout status deployment/petpaws-blue
  3. สลับ: kubectl patch svc petpaws -p '{"spec":{"selector":{"color":"blue"}}}'
  4. ยืนยัน: kubectl get endpoints petpaws ต้องชี้ IP ของ pod สี blue และทดสอบ API ผ่าน Service พอร์ต 8080
  5. แจ้งใน Slack และเปิด ticket แก้ build ที่เสีย ห้ามกด rebuild ซ้ำจนกว่าจะแก้โค้ด

R3: ย้อนเวอร์ชัน image

kubectl rollout history deployment/petpaws-green
kubectl rollout undo deployment/petpaws-green            # หรือ --to-revision=<N>
kubectl rollout status deployment/petpaws-green

จากนั้นใช้ R2 สลับทราฟฟิกไปสีที่ย้อนแล้ว ทางที่ถาวรกว่าคือ git revert commit ที่เสียแล้ว push เข้า main ให้ pipeline build และผ่านทุก gate ใหม่ (image ทุกตัวติด tag ตาม commit SHA: localhost:5001/petpaws-api:<sha> จึงย้อนได้ตรงตัว)

R4: Mobile

  • AAB ที่ลงนามแล้วของทุก build บน main ถูกเก็บเป็น artifact ใน job petpaws-mobile
  • Store ไม่ยอมรับ versionCode ที่ต่ำกว่าเดิม: ให้ git revert แล้วเพิ่มเลข build ใน pubspec.yaml (version: x.y.z+N) จากนั้นให้ pipeline สร้าง AAB ใหม่ด้วย keystore เดิม
  • ระหว่างรอ ให้หยุด staged rollout ของรุ่นที่มีปัญหาในหน้า console ของ store

R5: Infrastructure (Terraform / Ansible)

  1. git revert การแก้ใน infra/ แล้วรัน job petpaws-infra ด้วย ACTION=apply ตรวจ tfplan.txt ใน artifact ก่อนกดอนุมัติ
  2. ถ้า state เสีย: bucket petpaws-tfstate เปิด versioning ไว้ กู้เวอร์ชันก่อนหน้าด้วย aws --endpoint-url http://localstack:4566 s3api list-object-versions --bucket petpaws-tfstate แล้ว copy เวอร์ชันที่ต้องการทับ
  3. ถ้า lock ค้าง (build ถูกยกเลิกกลางคัน): ตรวจว่าไม่มี build อื่นรันอยู่ แล้ว terraform force-unlock <LOCK_ID>

หลัง rollback ทุกครั้ง

  • ตรวจ Grafana (:3003) ว่า success rate และคิว build กลับเป็นปกติ
  • ถ้าสาเหตุคือ secret รั่ว: เปลี่ยนค่าใน Jenkins Credentials และ Secret petpaws-env แล้ว restart deployment ทั้งสองสี
  • บันทึก postmortem: เวลา, build ที่เสีย, gate ไหนควรจับได้, สิ่งที่จะแก้
